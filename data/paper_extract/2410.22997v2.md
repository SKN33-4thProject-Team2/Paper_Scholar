# arXiv Paper: 2410.22997v2

## Abstract

<div class="ltx_abstract" id="abstract1"><h6 class="ltx_title ltx_title_abstract">Abstract</h6>
<p class="ltx_p" id="abstract1.1">Recent advances in <span class="ltx_glossaryref" title="Large Language Model">Large Language Models (LLMs)</span> have been instrumental in autonomous robot control and human-robot interaction by leveraging their vast general knowledge and capabilities to understand and reason across a wide range of tasks and scenarios. Previous works have investigated various prompt engineering techniques for improving the performance of <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> to accomplish tasks, while others have proposed methods that utilize LLMs to plan and execute tasks based on the available functionalities of a given robot platform. In this work, we consider both lines of research by comparing prompt engineering techniques and combinations thereof within the application of high-level task planning and execution in service robotics. We define a diverse set of tasks and a simple set of functionalities in simulation, and measure task completion accuracy and execution time for several state-of-the-art models. We make our code, including all prompts, available at <a class="ltx_ref ltx_url" href="https://github.com/AIS-Bonn/Prompt_Engineering" style="--ltx-fg-color:#0000FF;" title="">https://github.com/AIS-Bonn/Prompt_Engineering</a>.</p>
</div>

## I Introduction

<div class="ltx_para" id="S1.p1">
<p class="ltx_p" id="S1.p1.1">Since the unveiling of OpenAI’s ChatGPT in November 2022, the rapid emergence of Large Language Models (LLMs) as a major contributor to human-machine interaction has been rippling through society. With advances in scaling, instruction tuning, and alignment, models like GPT <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx1" title="">1</a>, <a class="ltx_ref" href="#bib.bibx2" title="">2</a>]</cite>, Gemini <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx3" title="">3</a>]</cite>, Llama <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx4" title="">4</a>]</cite>, or Mistral <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx5" title="">5</a>]</cite> can seemingly understand tasks presented in natural language and respond with answers in natural language that are often appropriate.</p>
</div><div class="ltx_para" id="S1.p2">
<p class="ltx_p" id="S1.p2.1">In this work, we investigate approaches that leverage these advances for robot control and human-robot interaction <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx6" title="">6</a>, <a class="ltx_ref" href="#bib.bibx7" title="">7</a>, <a class="ltx_ref" href="#bib.bibx8" title="">8</a>, <a class="ltx_ref" href="#bib.bibx9" title="">9</a>]</cite>, as well as prompt engineering techniques that aim to increase performance across various benchmarks <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx10" title="">10</a>, <a class="ltx_ref" href="#bib.bibx11" title="">11</a>, <a class="ltx_ref" href="#bib.bibx12" title="">12</a>]</cite>. In particular, we focus on comparing and combining prompt engineering techniques for the application of task planning and execution in the context of service robotics.</p>
</div><div class="ltx_para" id="S1.p3">
<p class="ltx_p" id="S1.p3.1">Many applications require autonomous robots to perform tasks in complex, cluttered, dynamic, or unknown environments. In order for such a robot to adapt to new tasks and environments, an expert is often required to understand the task logic and translate it into an implementation based on the robot’s capabilities. This severely limits speed and flexibility for robot deployment. <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> promise to relax this requirement while allowing for intelligent replanning during task execution. To this end, we focus on the challenging field of service robotics <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx13" title="">13</a>, <a class="ltx_ref" href="#bib.bibx14" title="">14</a>]</cite>, requiring robots to interact with non-expert operators in open-ended, highly unstructured environments designed for and shared with humans.</p>
</div><figure class="ltx_figure" id="S1.F1">
<figcaption class="ltx_caption ltx_centering"><span class="ltx_tag ltx_tag_figure">Fig. 1: </span>Overview of our simulated experimental setup to evaluate task completion. The user specifies a task in natural language. The action set describes the robot capabilities. Task planning and action selection are performed by prompting an <span class="ltx_glossaryref" title="Large Language Model">LLM</span>. The robot-environment simulation executes the action and provides feedback in form of a changed state.</figcaption>
</figure><div class="ltx_para" id="S1.p4">
<p class="ltx_p" id="S1.p4.1">To use an <span class="ltx_glossaryref" title="Large Language Model">LLM</span> for task planning, one must provide all the necessary information about the environment, the task, and the robot capabilities in textual form. Similarly, for task execution, the implementation of the robot’s high-level functionalities must be robust and general enough to account for unknown features of the environment and unexpected events during task execution. In this work, we obviate these problems by employing a simulated environment depicted in Figure <a class="ltx_ref" href="#S1.F1" title="Fig. 1 ‣ I Introduction ‣ A Comparison of Prompt Engineering Techniquesfor Task Planning and Execution in Service Robotics"><span class="ltx_text ltx_ref_tag">1</span></a> to systematically examine the effect of prompt engineering techniques on task completion across several types of tasks and state-of-the-art <span class="ltx_glossaryref" title="Large Language Model">LLMs</span>.</p>
</div><div class="ltx_para ltx_noindent" id="S1.p5">
<p class="ltx_p" id="S1.p5.1">The contributions of this paper are as follows:</p>
<ul class="ltx_itemize" id="S1.I1">
<li class="ltx_item" id="S1.I1.i1" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S1.I1.i1.p1">
<p class="ltx_p" id="S1.I1.i1.p1.1">We derive an <span class="ltx_glossaryref" title="Large Language Model">LLM</span>-based method allowing zero-shot task execution by sampling relevant action sequences from sets of pre-defined actions received via natural language commands from non-expert operators.</p>
</div></li>
<li class="ltx_item" id="S1.I1.i2" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S1.I1.i2.p1">
<p class="ltx_p" id="S1.I1.i2.p1.1">We thoroughly investigate and evaluate the feasibility and effectiveness of integrating <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> with various prompt engineering techniques for long-horizon tasks in the domain of service robotics.</p>
</div></li>
</ul>
</div>

## II Related Works

<div class="ltx_para" id="S2.p1">
<p class="ltx_p" id="S2.p1.1">Using <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> for high-level robot task planning and for low-level execution control are hot research topics <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx15" title="">15</a>, <a class="ltx_ref" href="#bib.bibx16" title="">16</a>]</cite>.</p>
</div><section class="ltx_subsection" id="S2.SS1">
<h3 class="ltx_title ltx_title_subsection"><span class="ltx_tag ltx_tag_subsection"><span class="ltx_text" id="S2.SS1.6">II-A</span> </span><span class="ltx_text ltx_font_italic" id="S2.SS1.7">Using <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> for Robot Task Planning &amp; Execution</span></h3>
<div class="ltx_para" id="S2.SS1.p1">
<p class="ltx_p" id="S2.SS1.p1.1">In recent years, <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> have been explored and adopted across a wide range of applications, motivated by harnessing the world knowledge extracted from the vast text data sets they have been trained on.</p>
</div>
<div class="ltx_para" id="S2.SS1.p2">
<p class="ltx_p" id="S2.SS1.p2.1"><cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx6" title="">6</a>]</cite> are among the proponents for high-level robot task planning using GPT. They outline the design principles of a robotics pipeline that integrates GPT to plan and implement task execution given an objective in textual form. They define a function library that implements various core functionalities for a given robot platform. They then let GPT generate code that implements a task given by a (non-technical) user based on this function library. Finally, the user can provide feedback and corrections to the code before approving it, allowing the robot to execute it. Their pipeline is evaluated in various domains such as manipulation, aerial navigation, and logical reasoning. This approach can generate complex code that incorporates appropriate branching to handle unexpected events during task execution, provided that the library functions support such information. However, the generated code must explicitly anticipate any such cases beforehand, as the method does not allow for dynamic replanning within GPT.</p>
</div>
<div class="ltx_para" id="S2.SS1.p3">
<p class="ltx_p" id="S2.SS1.p3.1"><cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx7" title="">7</a>]</cite> present a similar approach where a set of core functionalities is implemented for a given robot platform and exposed to an <span class="ltx_glossaryref" title="Large Language Model">LLM</span> input as context. Instead of relying on human feedback, they assign affordance values to all available functions and execute the highest-ranking one. They recalculate the affordance values before each function call to account for the current state of the robot and the environment.</p>
</div>
<div class="ltx_para" id="S2.SS1.p4">
<p class="ltx_p" id="S2.SS1.p4.1">Another <span class="ltx_glossaryref" title="Large Language Model">LLM</span>-based method for robot task planning is presented by <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx8" title="">8</a>]</cite>, combining strengths in common-sense reasoning and code understanding to generate executable plans. Their experiments demonstrate that incorporating programming language features enhances task performance and adapts well to diverse scenarios.</p>
</div>
<div class="ltx_para" id="S2.SS1.p5">
<p class="ltx_p" id="S2.SS1.p5.1"><cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx9" title="">9</a>]</cite> propose a method for open-world task planning and situation handling that dynamically integrates commonsense knowledge into a robot’s action knowledge, assesses the feasibility of progressing with the existing plan, or determines to adapt the plan accordingly. They integrate their approach on a real robot platform and demonstrate it executing service tasks in a domestic environment.</p>
</div>
</section><section class="ltx_subsection" id="S2.SS2">
<h3 class="ltx_title ltx_title_subsection"><span class="ltx_tag ltx_tag_subsection"><span class="ltx_text" id="S2.SS2.6">II-B</span> </span><span class="ltx_text ltx_font_italic" id="S2.SS2.7">Prompt Engineering Techniques</span></h3>
<div class="ltx_para" id="S2.SS2.p1">
<p class="ltx_p" id="S2.SS2.p1.1">While <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> are capable of performing tasks with zero-shot prompting <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx17" title="">17</a>]</cite>, they benefit from in-context examples with few-shot prompting <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx2" title="">2</a>]</cite>. To further improve performance on tasks requiring complex reasoning, a variety of prompt engineering techniques have been introduced <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx10" title="">10</a>]</cite>. In this work, we focus on comparing a selection of relevant and applicable prompt engineering techniques suitable for selecting and dynamically adapting sequences of function calls from a predefined library of functions to accomplish a given task.</p>
</div>
<div class="ltx_para" id="S2.SS2.p2">
<p class="ltx_p" id="S2.SS2.p2.1"><cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx11" title="">11</a>]</cite> introduced <span class="ltx_glossaryref" title="Chain-of-Thought">Chain-of-Thought (CoT)</span> prompting, which aims to improve performance on complex tasks by incorporating step-by-step reasoning into the responses provided. For natural language responses, this is easily achieved by modifying the original prompt to elicit step-by-step reasoning in the response. In the context of responses that contain function calls, we can first request step-by-step reasoning in a natural language response with a separate prompt before requesting one or multiple appropriate function calls based on that reasoning.</p>
</div>
<div class="ltx_para" id="S2.SS2.p3">
<p class="ltx_p" id="S2.SS2.p3.1"><cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx12" title="">12</a>]</cite> propose ReAct, which facilitates interleaved planning and action generation. Instead of planning ahead and then executing a complex multi-step plan without further reasoning and adapting to intermediate results, they introduce a discrete reasoning step between each action to ground reasoning in the results of past actions and update action plans accordingly.</p>
</div>
</section>

## III Dialogue with a Simulated Environment

<div class="ltx_para" id="S3.p1">
<p class="ltx_p" id="S3.p1.1">We investigate the effect of prompt engineering techniques across multiple tasks in a simulated environment. In this environment, the robot is provided with pre-defined functions from which an <span class="ltx_glossaryref" title="Large Language Model">LLM</span> must select and execute the appropriate ones to accomplish a task given in natural language. This process is modeled as a conversation between the robot and the LLM assistant. Once the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> signals that it has completed the task, we probe the environment to determine if the target condition indicating task success is met.</p>
</div><section class="ltx_subsection" id="S3.SS1">
<h3 class="ltx_title ltx_title_subsection"><span class="ltx_tag ltx_tag_subsection"><span class="ltx_text" id="S3.SS1.6">III-A</span> </span><span class="ltx_text ltx_font_italic" id="S3.SS1.7">Environment</span></h3>
<div class="ltx_para" id="S3.SS1.p1">
<p class="ltx_p" id="S3.SS1.p1.1">In order to create an environment that allows an accurate comparison of the effect of prompt engineering techniques, we adopt the setting found at RoboCup@Home <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx18" title="">18</a>, <a class="ltx_ref" href="#bib.bibx19" title="">19</a>]</cite>, which is a major international competition that focuses on domestic service robots.</p>
</div>
<div class="ltx_para" id="S3.SS1.p2">
<p class="ltx_p" id="S3.SS1.p2.1">The arena is designed to replicate a typical domestic dwelling with several rooms: A study room, a parlor, a kitchen, and a bedroom.
All tasks start with both robot and operator located in the parlor.
Each room contains multiple objects, including common food and household items, with which the robot can interact.</p>
</div>
</section><section class="ltx_subsection" id="S3.SS2">
<h3 class="ltx_title ltx_title_subsection"><span class="ltx_tag ltx_tag_subsection"><span class="ltx_text" id="S3.SS2.6">III-B</span> </span><span class="ltx_text ltx_font_italic" id="S3.SS2.7">Action Set</span></h3>
<div class="ltx_para" id="S3.SS2.p1">
<p class="ltx_p" id="S3.SS2.p1.1">We use the function-calling feature introduced by OpenAI’s API for their GPT line of models <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx2" title="">2</a>]</cite>, which is adopted by other <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> such as Mistral <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx5" title="">5</a>]</cite>, as well as several open-source inference pipelines. It allows for specifying the signatures of the pre-defined robot functions as a JSON schema. This exposes the function names, parameters, and parameter types, along with the corresponding natural language descriptions for all functions and parameters, to the context of the <span class="ltx_glossaryref" title="Large Language Model">LLM</span>. The <span class="ltx_glossaryref" title="Large Language Model">LLM</span> can then refer to these functions when generating natural language reasoning or planning, and it can call any of the functions, including the specification of parameter values, as JSON that can be easily parsed and passed to the simulation. The simulation then adjusts the state of the robot and environment accordingly, and returns a natural language text to the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> in response to the function call, providing relevant information about the success of the function and its effect on the robot and environment states.</p>
</div>
<div class="ltx_para ltx_noindent" id="S3.SS2.p2">
<p class="ltx_p" id="S3.SS2.p2.1">We define the same set of five functions for all tasks:</p>
</div>
<div class="ltx_para" id="S3.SS2.p3">
<ul class="ltx_itemize" id="S3.I1">
<li class="ltx_item" id="S3.I1.i1" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i1.p1">
<p class="ltx_p" id="S3.I1.i1.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i1.p1.1.1">drive_to_location(location_name):</span> This function moves the robot to the specified location. The available options are the exact names of the four rooms in the simulation: <span class="ltx_text ltx_font_italic" id="S3.I1.i1.p1.1.2">study</span>, <span class="ltx_text ltx_font_italic" id="S3.I1.i1.p1.1.3">parlor</span>, <span class="ltx_text ltx_font_italic" id="S3.I1.i1.p1.1.4">kitchen</span>, and <span class="ltx_text ltx_font_italic" id="S3.I1.i1.p1.1.5">bedroom</span>.</p>
</div></li>
<li class="ltx_item" id="S3.I1.i2" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i2.p1">
<p class="ltx_p" id="S3.I1.i2.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i2.p1.1.1">find_object(object_name_list):</span> The argument of this function is a list of strings that refer to object names the robot will search for in the room it is in. These object names must exactly match the object names specified for each room in the simulation. For each of the objects, the function returns the number of instances found in the room.</p>
</div></li>
<li class="ltx_item" id="S3.I1.i3" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i3.p1">
<p class="ltx_p" id="S3.I1.i3.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i3.p1.1.1">grasp_object(object_name):</span> Once an object has been found, this function lets the robot grasp the specified object. Again, the name of the object must exactly match an object available in the current room. As an additional constraint, the robot can never carry more than two objects at the same time.</p>
</div></li>
<li class="ltx_item" id="S3.I1.i4" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i4.p1">
<p class="ltx_p" id="S3.I1.i4.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i4.p1.1.1">place_object(object_name):</span> This function makes the robot place the specified object that is being carried in the current room that the robot is in.</p>
</div></li>
<li class="ltx_item" id="S3.I1.i5" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i5.p1">
<p class="ltx_p" id="S3.I1.i5.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i5.p1.1.1">exit():</span> A call to this function signals that the task objective has been accomplished and gracefully terminates the simulation run to the target condition.</p>

<p class="ltx_p" id="S3.SS3.p2.1">We define the following four tasks:</p>
</div>
<section class="ltx_subsubsection" id="S3.SS3.SSS1">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S3.SS3.SSS1.6">III-C</span>1 </span>Fetch</h4>
<div class="ltx_para" id="S3.SS3.SSS1.p1">
<p class="ltx_p" id="S3.SS3.SSS1.p1.1">The Fetch task requires the robot to pick up an object from another location and to return it to the user. Since Fetch can be solved with a simple sequence of function calls, it mainly tests whether the <span class="ltx_glossaryref" title="Large Language Model">LLM</span>, in combination with the applied prompt engineering technique, is able to comprehend the scenario, use the function-calling feature, and generate valid JSON appropriate to solve the task. An example of Fetch is: "Please get me a pen from the study".</p>
</div>
</section>
<section class="ltx_subsubsection" id="S3.SS3.SSS2">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S3.SS3.SSS2.6">III-C</span>2 </span>Conditional</h4>
<div class="ltx_para" id="S3.SS3.SSS2.p1">
<p class="ltx_p" id="S3.SS3.SSS2.p1.1">The Conditional task extends Fetch by adding the requirement to gather knowledge about the environment during task execution and to adapt its behavior accordingly. In particular, the robot is asked to search for an object and return one of two other objects to the user. The choice of the latter depends on the first object found. This task therefore tests whether the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> is capable of branching logic. An example of Conditional is: "Check if there is a spoon in the kitchen. If you find one, bring me a pen from the study. If not, bring me a comb from the bedroom".</p>
</div>
</section>
<section class="ltx_subsubsection" id="S3.SS3.SSS3">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S3.SS3.SSS3.6">III-C</span>3 </span>Equals</h4>
<div class="ltx_para" id="S3.SS3.SSS3.p1">
<p class="ltx_p" id="S3.SS3.SSS3.p1.1">The Equals task requires the robot to make a numerical observation and repeatedly retrieve an object according to that observation. It therefore tests basic mathematical ability and requires the execution of a logical loop. This results in a long task that requires many function calls, challenging the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to maintain focus on accomplishing the task objective. An example of Equals is: "For every orange in the kitchen, move a fork from the kitchen to the parlor".</p>
</div>
</section>
<section class="ltx_subsubsection" id="S3.SS3.SSS4">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S3.SS3.SSS4.6">III-C</span>4 </span>Distribute</h4>
<div class="ltx_para" id="S3.SS3.SSS4.p1">
<p class="ltx_p" id="S3.SS3.SSS4.p1.1">In the Distribute task, a given object must be distributed so that every location in the simulation contains at least one instance. The <span class="ltx_glossaryref" title="Large Language Model">LLM</span> must therefore not only visit all locations, but also make numerous decisions regarding the movement of objects and keep track of their locations. An example of Distribute is: "Please distribute the pens evenly so that each location contains at least one pen. You can start with the pens in the study".</p>
</div>
</section>
</section>

## III-A Environment

<div class="ltx_para" id="S3.SS1.p1">
<p class="ltx_p" id="S3.SS1.p1.1">In order to create an environment that allows an accurate comparison of the effect of prompt engineering techniques, we adopt the setting found at RoboCup@Home <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx18" title="">18</a>, <a class="ltx_ref" href="#bib.bibx19" title="">19</a>]</cite>, which is a major international competition that focuses on domestic service robots.</p>
</div><div class="ltx_para" id="S3.SS1.p2">
<p class="ltx_p" id="S3.SS1.p2.1">The arena is designed to replicate a typical domestic dwelling with several rooms: A study room, a parlor, a kitchen, and a bedroom.
All tasks start with both robot and operator located in the parlor.
Each room contains multiple objects, including common food and household items, with which the robot can interact.</p>
</div>

## III-B Action Set

<div class="ltx_para" id="S3.SS2.p1">
<p class="ltx_p" id="S3.SS2.p1.1">We use the function-calling feature introduced by OpenAI’s API for their GPT line of models <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx2" title="">2</a>]</cite>, which is adopted by other <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> such as Mistral <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx5" title="">5</a>]</cite>, as well as several open-source inference pipelines. It allows for specifying the signatures of the pre-defined robot functions as a JSON schema. This exposes the function names, parameters, and parameter types, along with the corresponding natural language descriptions for all functions and parameters, to the context of the <span class="ltx_glossaryref" title="Large Language Model">LLM</span>. The <span class="ltx_glossaryref" title="Large Language Model">LLM</span> can then refer to these functions when generating natural language reasoning or planning, and it can call any of the functions, including the specification of parameter values, as JSON that can be easily parsed and passed to the simulation. The simulation then adjusts the state of the robot and environment accordingly, and returns a natural language text to the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> in response to the function call, providing relevant information about the success of the function and its effect on the robot and environment states.</p>
</div><div class="ltx_para ltx_noindent" id="S3.SS2.p2">
<p class="ltx_p" id="S3.SS2.p2.1">We define the same set of five functions for all tasks:</p>
</div><div class="ltx_para" id="S3.SS2.p3">
<ul class="ltx_itemize" id="S3.I1">
<li class="ltx_item" id="S3.I1.i1" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i1.p1">
<p class="ltx_p" id="S3.I1.i1.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i1.p1.1.1">drive_to_location(location_name):</span> This function moves the robot to the specified location. The available options are the exact names of the four rooms in the simulation: <span class="ltx_text ltx_font_italic" id="S3.I1.i1.p1.1.2">study</span>, <span class="ltx_text ltx_font_italic" id="S3.I1.i1.p1.1.3">parlor</span>, <span class="ltx_text ltx_font_italic" id="S3.I1.i1.p1.1.4">kitchen</span>, and <span class="ltx_text ltx_font_italic" id="S3.I1.i1.p1.1.5">bedroom</span>.</p>
</div></li>
<li class="ltx_item" id="S3.I1.i2" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i2.p1">
<p class="ltx_p" id="S3.I1.i2.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i2.p1.1.1">find_object(object_name_list):</span> The argument of this function is a list of strings that refer to object names the robot will search for in the room it is in. These object names must exactly match the object names specified for each room in the simulation. For each of the objects, the function returns the number of instances found in the room.</p>
</div></li>
<li class="ltx_item" id="S3.I1.i3" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i3.p1">
<p class="ltx_p" id="S3.I1.i3.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i3.p1.1.1">grasp_object(object_name):</span> Once an object has been found, this function lets the robot grasp the specified object. Again, the name of the object must exactly match an object available in the current room. As an additional constraint, the robot can never carry more than two objects at the same time.</p>
</div></li>
<li class="ltx_item" id="S3.I1.i4" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i4.p1">
<p class="ltx_p" id="S3.I1.i4.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i4.p1.1.1">place_object(object_name):</span> This function makes the robot place the specified object that is being carried in the current room that the robot is in.</p>
</div></li>
<li class="ltx_item" id="S3.I1.i5" style="list-style-type:none;"><span class="ltx_tag ltx_tag_item">•</span>
<div class="ltx_para" id="S3.I1.i5.p1">
<p class="ltx_p" id="S3.I1.i5.p1.1"><span class="ltx_text ltx_font_typewriter" id="S3.I1.i5.p1.1.1">exit():</span> A call to this function signals that the task objective has been accomplished and gracefully terminates the simulation run to the target condition.</p>
</div></li>
</ul>
</div><div class="ltx_para" id="S3.SS2.p4">
<p class="ltx_p" id="S3.SS2.p4.1">If the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> returns an invalid function call with respect to the specified JSON schema, the simulation run is considered a failure. If the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> specifies a function parameter that is invalid with respect to the function being unable to execute its intended objective, the function returns a response briefly explaining the problem so that the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> can adapt and continue the simulation run. Each simulation run is automatically terminated and tested for meeting the target condition after 40 function calls have been executed.</p>
</div>

<p class="ltx_p" id="S3.SS3.p2.1">We define the following four tasks:</p>
</div><section class="ltx_subsubsection" id="S3.SS3.SSS1">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S3.SS3.SSS1.6">III-C</span>1 </span>Fetch</h4>
<div class="ltx_para" id="S3.SS3.SSS1.p1">
<p class="ltx_p" id="S3.SS3.SSS1.p1.1">The Fetch task requires the robot to pick up an object from another location and to return it to the user. Since Fetch can be solved with a simple sequence of function calls, it mainly tests whether the <span class="ltx_glossaryref" title="Large Language Model">LLM</span>, in combination with the applied prompt engineering technique, is able to comprehend the scenario, use the function-calling feature, and generate valid JSON appropriate to solve the task. </div>
</section><section class="ltx_subsubsection" id="S3.SS3.SSS2">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S3.SS3.SSS2.6">III-C</span>2 </span>Conditional</h4>
<div class="ltx_para" id="S3.SS3.SSS2.p1">
<p class="ltx_p" id="S3.SS3.SSS2.p1.1">The Conditional task extends Fetch by adding the requirement to gather knowledge about the environment during task execution and to adapt its behavior accordingly. In particular, the robot is asked to search for an object and return one of two other objects to the user. The choice of the latter depends on the first object found. This task therefore tests whether the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> is capable of branching logic. An example of Conditional is: "Check if there is a spoon in the kitchen. If you find one, bring me a pen from the study. If not, bring me a comb from the bedroom".</p>
</div>
</section><section class="ltx_subsubsection" id="S3.SS3.SSS3">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S3.SS3.SSS3.6">III-C</span>3 </span>Equals</h4>
<div class="ltx_para" id="S3.SS3.SSS3.p1">
<p class="ltx_p" id="S3.SS3.SSS3.p1.1">The Equals task requires the robot to make a numerical observation and repeatedly retrieve an object according to that observation. It therefore tests basic mathematical ability and requires the execution of a logical loop. This results in a long task that requires many function calls, challenging the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to maintain focus on accomplishing the task objective. An example of Equals is: "For every orange in the kitchen, move a fork from the kitchen to the parlor".</p>
</div>
</section><section class="ltx_subsubsection" id="S3.SS3.SSS4">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S3.SS3.SSS4.6">III-C</span>4 </span>Distribute</h4>
<div class="ltx_para" id="S3.SS3.SSS4.p1">
<p class="ltx_p" id="S3.SS3.SSS4.p1.1">In the Distribute task, a given object must be distributed so that every location in the simulation contains at least one instance. The <span class="ltx_glossaryref" title="Large Language Model">LLM</span> must therefore not only visit all locations, but also make numerous decisions regarding the movement of objects and keep track of their locations. An example of Distribute is: "Please distribute the pens evenly so that each location contains at least one pen. You can start with the pens in the study".</p>
</div>
</section>

## IV Experiments

<section class="ltx_subsection" id="S4.SS1">
<h3 class="ltx_title ltx_title_subsection"><span class="ltx_tag ltx_tag_subsection"><span class="ltx_text" id="S4.SS1.6">IV-A</span> </span><span class="ltx_glossaryref ltx_font_italic" title="Large Language Model">LLM</span><span class="ltx_text ltx_font_italic" id="S4.SS1.7"> Variants</span></h3>
<div class="ltx_para" id="S4.SS1.p1">
<p class="ltx_p" id="S4.SS1.p1.1">We focus on evaluating GPT <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx2" title="">2</a>]</cite> model variants, due to the function-calling feature of the corresponding API, and their top-of-the-line results on benchmarks regarding this feature <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx20" title="">20</a>]</cite>. In particular, we use GPT-3.5-Turbo-0125 and GPT-4-0125-Preview, referred to as GPT 4 Turbo.
We evaluate each condition with respect to tasks and prompt engineering techniques with 50 repetitions for GPT 3.5 Turbo and 20 repetitions for GPT 4 Turbo due to budgetary considerations.
For both model variants and all tasks, we use a temperature setting of <math alttext="\tau=0" class="ltx_Math" display="inline" id="S4.SS1.p1.m1" intent=":literal"><semantics><mrow><mi>τ</mi><mo>=</mo><mn>0</mn></mrow><annotation encoding="application/x-tex">\tau=0</annotation></semantics></math> to elicit factual responses. All other model parameters are set to the default values suggested by OpenAI.</p>
</div>
</section><section class="ltx_subsection" id="S4.SS2">
<h3 class="ltx_title ltx_title_subsection"><span class="ltx_tag ltx_tag_subsection"><span class="ltx_text" id="S4.SS2.6">IV-B</span> </span><span class="ltx_text ltx_font_italic" id="S4.SS2.7">Prompt Engineering Techniques</span></h3>
<div class="ltx_para" id="S4.SS2.p1">
<p class="ltx_p" id="S4.SS2.p1.1">Our simulation procedure allows the robot to execute tasks immediately after providing the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> with the task description along with the function definitions in an initial prompt. Task completion then proceeds as a dialog of function calls generated by the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> and corresponding function responses generated by the simulation. This approach serves as a baseline for investigating and comparing the effects of various prompt engineering techniques on task completion and time required. We focus on a selection of popular and applicable prompt engineering techniques for task planning and execution in the service robotics domain. Figure <a class="ltx_ref" href="#S3.F2" title="Fig. 2 ‣ III-C Tasks ‣ III Dialogue with a Simulated Environment ‣ A Comparison of Prompt Engineering Techniquesfor Task Planning and Execution in Service Robotics"><span class="ltx_text ltx_ref_tag">2</span></a> gives an overview of this selection.</p>
</div>
<div class="ltx_para" id="S4.SS2.p2">
<p class="ltx_p" id="S4.SS2.p2.1">We investigate (combinations of) the following five prompt engineering techniques:</p>
</div>
<section class="ltx_subsubsection" id="S4.SS2.SSS1">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS1.6">IV-B</span>1 </span>Adaptive Functions</h4>
<div class="ltx_para" id="S4.SS2.SSS1.p1">
<p class="ltx_p" id="S4.SS2.SSS1.p1.1">Based on the robot’s state and its knowledge of the environment, we can deduce that certain functions cannot accomplish their intended objective. For example, the robot cannot place an object if it is not currently carrying at least one. Similarly, the robot cannot grasp an object if it is already carrying the specified maximum capacity of two objects. Since the tool-calling feature of the targeted API provides the capability to specify the set of available functions with each prompt, we can exclude such functions accordingly. This approach effectively prevents the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> from calling those functions. While this is a useful feature for guard-railing the system in general, we intend to use it to reduce the number of failed function calls, and instead focus the <span class="ltx_glossaryref" title="Large Language Model">LLM</span>’s attention on viable functions. We refer to this technique as Adaptive Functions.</p>
</div>
</section>
<section class="ltx_subsubsection" id="S4.SS2.SSS2">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS2.6">IV-B</span>2 </span>Chain-of-Thought (CoT)</h4>
<div class="ltx_para" id="S4.SS2.SSS2.p1">
<p class="ltx_p" id="S4.SS2.SSS2.p1.1">We integrate <span class="ltx_glossaryref" title="Chain-of-Thought">CoT</span> <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx11" title="">11</a>]</cite> prompting into our framework by asking the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to first provide a textual step-by-step plan detailing how it intends to complete the task given the available functions from the function library. Only after such a plan has been generated, we ask the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to call the appropriate functions based on that plan. If the task execution turns out to require many steps, we repeat this planning step every 15 function calls, to ensure that the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> is always operating according to a plan in case the initial plan is not detailed enough or incomplete.</p>
</div>
</section>
<section class="ltx_subsubsection" id="S4.SS2.SSS3">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS3.6">IV-B</span>3 </span>Reasoning and Acting (ReAct)</h4>
<div class="ltx_para" id="S4.SS2.SSS3.p1">
<p class="ltx_p" id="S4.SS2.SSS3.p1.1">While <span class="ltx_glossaryref" title="Chain-of-Thought">CoT</span> can be characterized as planning a task in advance, likely involving multiple steps, and then executing the plan without explicitly adapting the original plan or any further reasoning. This may not be sufficient when unexpected or difficult-to-anticipate events occur during task execution. To address this problem,
we use ReAct <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx12" title="">12</a>]</cite> to maintain a tight coupling between task execution and reasoning, by explicitly enforcing the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to alternate between the two with dedicated prompts. This also has the advantage of making the decisions of the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> easily interpretable by looking at the generated reasoning in relation to the generated behavior. This is a useful tool for manually refining function and parameter descriptions.</p>
</div>
</section>
<section class="ltx_subsubsection" id="S4.SS2.SSS4">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS4.6">IV-B</span>4 </span>Example in Prompt</h4>
<div class="ltx_para" id="S4.SS2.SSS4.p1">
<p class="ltx_p" id="S4.SS2.SSS4.p1.1">Guiding the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> with a human-annotated example prior to actual task planning and execution, as suggested by <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx11" title="">11</a>]</cite> and <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx12" title="">12</a>]</cite>, helps to remove ambiguity regarding the interpretation of task and function descriptions, and is often combined with other prompting techniques. Specifically, we prepend a human-expert generated example of a successful Equals task to the context of the <span class="ltx_glossaryref" title="Large Language Model">LLM</span>, including the task description and all function calls and responses. The example is designed to be different from any evaluated experimental task.</p>
</div>

<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS5.6">IV-B</span>5 </span>State Description</h4>
<div class="ltx_para" id="S4.SS2.SSS5.p1">
<p class="ltx_p" id="S4.SS2.SSS5.p1.1">Finally, we introduce a prompt engineering technique that summarizes the robot’s state and knowledge of the environment at the end of the context for before each prompt. Since many tasks involve a long horizon, it can be difficult for the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to accurately assess this information when it is required to gather and deduce it from the entire context. These summaries, which we refer to as state descriptions, attempt to mitigate this challenge. To reduce the number of tokens the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> is prompted with, the context will only ever contain a single state description at the very end of the context. Thus, previous state descriptions are removed from the context with each prompt.</p>
</div>
<div class="ltx_para" id="S4.SS2.SSS5.p2">
<p class="ltx_p" id="S4.SS2.SSS5.p2.1">A state description contains information about known objects and their locations, as perceived by the robot. It also details whether the robot is carrying any objects, if so, which ones, and the location of both the robot and the operator.</p>
</div>

For both model variants and all tasks, we use a temperature setting of <math alttext="\tau=0" class="ltx_Math" display="inline" id="S4.SS1.p1.m1" intent=":literal"><semantics><mrow><mi>τ</mi><mo>=</mo><mn>0</mn></mrow><annotation encoding="application/x-tex">\tau=0</annotation></semantics></math> to elicit factual responses. All other model parameters are set to the default values suggested by OpenAI.</p>

## IV-B Prompt Engineering Techniques

<div class="ltx_para" id="S4.SS2.p1">
<p class="ltx_p" id="S4.SS2.p1.1">Our simulation procedure allows the robot to execute tasks immediately after providing the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> with the task description along with the function definitions in an initial prompt. Task completion then proceeds as a dialog of function calls generated by the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> and corresponding function responses generated by the simulation. This approach serves as a baseline for investigating and comparing the effects of various prompt engineering techniques on task completion and time required. We focus on a selection of popular and applicable prompt engineering techniques for task planning and execution in the service robotics domain. Figure <a class="ltx_ref" href="#S3.F2" title="Fig. 2 ‣ III-C Tasks ‣ III Dialogue with a Simulated Environment ‣ A Comparison of Prompt Engineering Techniquesfor Task Planning and Execution in Service Robotics"><span class="ltx_text ltx_ref_tag">2</span></a> gives an overview of this selection.</p>
</div><div class="ltx_para" id="S4.SS2.p2">
<p class="ltx_p" id="S4.SS2.p2.1">We investigate (combinations of) the following five prompt engineering techniques:</p>
</div><section class="ltx_subsubsection" id="S4.SS2.SSS1">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS1.6">IV-B</span>1 </span>Adaptive Functions</h4>
<div class="ltx_para" id="S4.SS2.SSS1.p1">
<p class="ltx_p" id="S4.SS2.SSS1.p1.1">Based on the robot’s state and its knowledge of the environment, we can deduce that certain functions cannot accomplish their intended objective. For example, the robot cannot place an object if it is not currently carrying at least one. Similarly, the robot cannot grasp an object if it is already carrying the specified maximum capacity of two objects. Since the tool-calling feature of the targeted API provides the capability to specify the set of available functions with each prompt, we can exclude such functions accordingly. This approach effectively prevents the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> from calling those functions. While this is a useful feature for guard-railing the system in general, we intend to use it to reduce the number of failed function calls, and instead focus the <span class="ltx_glossaryref" title="Large Language Model">LLM</span>’s attention on viable functions. We refer to this technique as Adaptive Functions.</p>
</div>
</section><section class="ltx_subsubsection" id="S4.SS2.SSS2">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS2.6">IV-B</span>2 </span>Chain-of-Thought (CoT)</h4>
<div class="ltx_para" id="S4.SS2.SSS2.p1">
<p class="ltx_p" id="S4.SS2.SSS2.p1.1">We integrate <span class="ltx_glossaryref" title="Chain-of-Thought">CoT</span> <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx11" title="">11</a>]</cite> prompting into our framework by asking the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to first provide a textual step-by-step plan detailing how it intends to complete the task given the available functions from the function library. Only after such a plan has been generated, we ask the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to call the appropriate functions based on that plan. If the task execution turns out to require many steps, we repeat this planning step every 15 function calls, to ensure that the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> is always operating according to a plan in case the initial plan is not detailed enough or incomplete.</p>
</div>
</section><section class="ltx_subsubsection" id="S4.SS2.SSS3">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS3.6">IV-B</span>3 </span>Reasoning and Acting (ReAct)</h4>
<div class="ltx_para" id="S4.SS2.SSS3.p1">
<p class="ltx_p" id="S4.SS2.SSS3.p1.1">While <span class="ltx_glossaryref" title="Chain-of-Thought">CoT</span> can be characterized as planning a task in advance, likely involving multiple steps, and then executing the plan without explicitly adapting the original plan or any further reasoning. This may not be sufficient when unexpected or difficult-to-anticipate events occur during task execution. To address this problem,
we use ReAct <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx12" title="">12</a>]</cite> to maintain a tight coupling between task execution and reasoning, by explicitly enforcing the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to alternate between the two with dedicated prompts. This also has the advantage of making the decisions of the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> easily interpretable by looking at the generated reasoning in relation to the generated behavior. This is a useful tool for manually refining function and parameter descriptions.</p>
</div>
</section><section class="ltx_subsubsection" id="S4.SS2.SSS4">
<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS4.6">IV-B</span>4 </span>Example in Prompt</h4>
<div class="ltx_para" id="S4.SS2.SSS4.p1">
<p class="ltx_p" id="S4.SS2.SSS4.p1.1">Guiding the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> with a human-annotated example prior to actual task planning and execution, as suggested by <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx11" title="">11</a>]</cite> and <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx12" title="">12</a>]</cite>, helps to remove ambiguity regarding the interpretation of task and function descriptions, and is often combined with other prompting techniques. Specifically, we prepend a human-expert generated example of a successful Equals task to the context of the <span class="ltx_glossaryref" title="Large Language Model">LLM</span>, including the task description and all function calls and responses. The example is designed to be different from any evaluated experimental task.</p>
</div>

<h4 class="ltx_title ltx_title_subsubsection"><span class="ltx_tag ltx_tag_subsubsection"><span class="ltx_text" id="S4.SS2.SSS5.6">IV-B</span>5 </span>State Description</h4>
<div class="ltx_para" id="S4.SS2.SSS5.p1">
<p class="ltx_p" id="S4.SS2.SSS5.p1.1">Finally, we introduce a prompt engineering technique that summarizes the robot’s state and knowledge of the environment at the end of the context for before each prompt. Since many tasks involve a long horizon, it can be difficult for the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> to accurately assess this information when it is required to gather and deduce it from the entire context. These summaries, which we refer to as state descriptions, attempt to mitigate this challenge. To reduce the number of tokens the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> is prompted with, the context will only ever contain a single state description at the very end of the context. Thus, previous state descriptions are removed from the context with each prompt.</p>
</div>
<div class="ltx_para" id="S4.SS2.SSS5.p2">
<p class="ltx_p" id="S4.SS2.SSS5.p2.1">A state description contains information about known objects and their locations, as perceived by the robot. It also details whether the robot is carrying any objects, if so, which ones, and the location of both the robot and the operator.</p>
</div>
</section>

</figure><div class="ltx_para" id="S5.p1">
<p class="ltx_p" id="S5.p1.1">For illustration, Figure <a class="ltx_ref" href="#S5.F3" title="Fig. 3 ‣ V Results ‣ A Comparison of Prompt Engineering Techniquesfor Task Planning and Execution in Service Robotics"><span class="ltx_text ltx_ref_tag">3</span></a> shows a sample transcript of a Fetch task using GPT 4 Turbo and CoT prompting. The averaged results of our experiments for all tasks and prompt engineering techniques are shown in Table <a class="ltx_ref" href="#S3.T1" title="TABLE I ‣ III-C Tasks ‣ III Dialogue with a Simulated Environment ‣ A Comparison of Prompt Engineering Techniquesfor Task Planning and Execution in Service Robotics"><span class="ltx_text ltx_ref_tag">I</span></a> for GPT 3.5 Turbo and in Table <a class="ltx_ref" href="#S4.T2" title="TABLE II ‣ IV-B4 Example in Prompt ‣ IV-B Prompt Engineering Techniques ‣ IV Experiments ‣ A Comparison of Prompt Engineering Techniquesfor Task Planning and Execution in Service Robotics"><span class="ltx_text ltx_ref_tag">II</span></a> for GPT 4 Turbo. For all test conditions, we report the success rate and the average time required to generate a sample. Note that these times only reflect the time spent waiting for LLM responses from the OpenAI API, while the required time of robot actions and simulation feedback can be considered negligible.</p>
</div><div class="ltx_para" id="S5.p2">
<p class="ltx_p" id="S5.p2.1">On the Fetch task, GPT 4 Turbo achieves a perfect success rate for all prompting techniques. In comparison, GPT 3.5 Turbo requires more complex prompting techniques to achieve a high success rate. The baseline for GPT 3.5 Turbo fails to solve the task in almost all cases.
Using adaptive functions, <span class="ltx_glossaryref" title="Chain-of-Thought">CoT</span> or state descriptions increases the success rate. A perfect success rate for GPT 3.5 Turbo is only achieved by providing an example. Similar results can be observed for the success rate of the Conditional task with GPT 4 Turbo. Again, a perfect success rate is only achieved by providing an example.
For the Conditional task with GPT 3.5 Turbo, we observe a significant drop in the success rate when an example is missing. This supports the argument that <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> are few-shot learners <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx2" title="">2</a>]</cite>. However, a single example seems to be sufficient to accomplish the task at hand.</p>
</div><div class="ltx_para" id="S5.p3">
<p class="ltx_p" id="S5.p3.1">We find that more complex prompt engineering techniques do not necessarily lead to higher success rates. On the Equals and Distribute tasks with GPT 3.5 Turbo, the techniques without state descriptions outperform the corresponding technique with state descriptions. However, state descriptions do not always have a negative impact. For the GPT 3.5 Turbo Conditional task, the addition of state descriptions (AF + ReAct + EiP + StD) achieves the highest success rate of 72%. We also observe that using only adaptive functions achieves the best success rate with GPT 4 Turbo for the Distribute task, while achieving the worst success rate for the Conditional and Equals tasks. There is also no clear favorite between <span class="ltx_glossaryref" title="Chain-of-Thought">CoT</span> and ReAct, as the success rates vary depending on the task, model variant, and other prompt engineering techniques used in conjunction.</p>
</div><div class="ltx_para" id="S5.p4">
<p class="ltx_p" id="S5.p4.1">Due to the additional prompts used in all prompting techniques besides the adaptive functions, the measured task completion time depends on the technique used. In general, we observe that <span class="ltx_glossaryref" title="Chain-of-Thought">CoT</span> and even more so ReAct show a longer runtime due to the relatively large number of tokens generated by the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> for planning and reasoning compared to function calls. Using state descriptions increases the time even more for the same reason. Even though the adaptive functions do not utilize additional prompts, we can see a slight reduction in time compared to the baseline, because the <span class="ltx_glossaryref" title="Large Language Model">LLM</span> is less likely to call functions that result in failures. In a real application, the response time of an <span class="ltx_glossaryref" title="Large Language Model">LLM</span> can significantly increase the execution time of a task, although functions that require considerable time themselves provide leeway to mask this problem.</p>
</div><div class="ltx_para" id="S5.p5">
<p class="ltx_p" id="S5.p5.1">We have successfully used GPT for task planning and execution in several service robotics tasks. We show that the use of appropriate prompt engineering techniques can effectively improve performance. However, overall performance is significantly dependent on the model variant used.</p>
</div>

## VI Conclusion

<div class="ltx_para" id="S6.p1">
<p class="ltx_p" id="S6.p1.1">In this work, we demonstrated the use of <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> to understand user commands to plan and execute tasks given an action set and an environment state in the context of service robotics. We evaluated several prompt engineering techniques in a simulated environment, across different tasks and models. GPT 3.5 Turbo performed well on simpler tasks using advanced prompt engineering techniques, but struggled with complex scenarios. GPT 4 Turbo managed to complete complex tasks with mixed reliability, while significantly outperforming GPT 3.5 Turbo on simpler tasks.</p>
</div><div class="ltx_para" id="S6.p2">
<p class="ltx_p" id="S6.p2.1">We found that while <span class="ltx_glossaryref" title="Chain-of-Thought">CoT</span> <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx11" title="">11</a>]</cite> and ReAct <cite class="ltx_cite ltx_citemacro_cite">[<a class="ltx_ref" href="#bib.bibx12" title="">12</a>]</cite> improve task completion rates, the best performance is achieved when combined with an example of a successful completion of a related task. This provides an opportunity for human expert knowledge within a task domain or about the robot platform to contribute to the tuning of a robot’s behavior.</p>
</div><div class="ltx_para" id="S6.p3">
<p class="ltx_p" id="S6.p3.1">Augmenting robotic systems with the reasoning capabilities of <span class="ltx_glossaryref" title="Large Language Model">LLMs</span> through prompt engineering techniques is a promising area of research. It enables progress toward general-purpose service robots capable of operating in challenging open-ended environments where classical approaches to task planning and execution reach their limits. However, to achieve this goal, work on prompt engineering techniques will remain essential to enable safe and reliable task planning and execution while providing adaptability to environments and robot platforms.</p>
</div>

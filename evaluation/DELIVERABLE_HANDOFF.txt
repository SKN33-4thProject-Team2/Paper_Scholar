[내일 Codex에게 전달할 작업 인수인계 메모]

작성 목적
---------
학술 논문 RAG Chatbot 프로젝트의 평가 작업과 제출 산출물 준비를 이어서 진행하기 위한 메모입니다.
아래 내용을 먼저 읽고, 기존 프로젝트 코드는 수정하지 않은 상태에서 필요한 산출물만 준비하세요.

1. 가장 중요한 작업 제약
--------------------------
- 폴더 구조를 임의로 변경하지 않습니다.
- evaluation/ 밖의 파일은 승인 없이 수정하지 않습니다.
- 특히 main.py, web_app.py, src/, data/, tests/는 절대 수정하지 않습니다.
- Streamlit 화면은 만들거나 수정하지 않습니다.
- .env, API 키, LangSmith 키는 커밋하거나 제출하지 않습니다.
- 새 작업이 필요하면 먼저 수정 대상 파일과 이유를 사용자에게 보여주고 확인받습니다.

2. 현재까지 완료한 내용
------------------------
- 평가 전용 corpus_v3를 evaluation/corpus_v3/ 아래에 구성했습니다.
- 논문 40편을 manifest로 고정했습니다.
- 후보 문항 은행은 총 650건입니다.
- 실제 실행 예산은 사용자가 400건으로 확정했습니다.
- 400건 배분:
  artifacts 40 / retrieval 240 / deep_research 40 / pipeline 40 / refusal 40
- 모든 논문이 평가 표본에 균형 있게 포함되어 있습니다.
- 평가 전용 LangGraph 런타임을 만들었고 운영 DB와 분리했습니다.
- 검색 구간 지표(Passage Section Recall@5, Section MRR)를 추가했습니다.
- LangSmith에 캐시 결과 기반 5개 suite 실험을 등록했습니다.
- RAGAS, DeepEval, Promptfoo 어댑터는 evaluation 결과를 사용하도록 정리했습니다.

4. 다른 노트북에서 재현하는 방법
----------------------------------
PR에는 코드, manifest, dataset_v3.jsonl, 평가 설명서와 요약 리포트만 포함되어 있습니다.
PDF, 평가 DB, 실행 결과 JSONL, 로그는 용량 때문에 커밋하지 않았습니다.

새 노트북에서 처음부터 실행하려면:

1) GitHub 저장소를 최신 main 또는 평가 브랜치에서 받습니다.
2) 프로젝트 requirements.txt를 설치합니다.
3) 필요한 경우 evaluation/requirements.txt를 별도 평가 환경에 설치합니다.
4) .env에 OPENAI_API_KEY를 설정합니다. 키는 문서나 GitHub에 기록하지 않습니다.
5) 평가 코퍼스를 생성합니다.

   python evaluation/corpus_v3/build_corpus.py

   인터넷이 없으면 arXiv에서 내려받는 PDF가 준비되지 않으므로 실행할 수 없습니다.
6) 400건 평가를 실행합니다.

   python -m evaluation.run_v3_evaluation --suite all --answer-mode openai --budget 400

주의:
- 실행 결과 캐시가 없으면 OpenAI 모델을 최대 400건 호출하므로 토큰이 사용됩니다.
- 모델 응답이 달라지면 지표가 약간 달라질 수 있습니다.
- 현재 결과를 토큰 없이 그대로 확인하려면 기존 컴퓨터의
  evaluation/corpus_v3/generated/execution_results_v3.jsonl을 별도로 복사해야 합니다.
- 이 캐시 파일은 대용량 생성 산출물이므로 GitHub에 올리지 않습니다.

5. 산출물 제출 지침
--------------------

최종 제출 또는 발표 자료에는 다음을 사용합니다.
- 평가 건수 및 suite별 배분
- evaluation_summary_v3.json의 주요 지표
- LangSmith 실험 링크
- 검색 구간 지표가 0.40 수준이며 인용 정밀도 개선이 필요하다는 한계
